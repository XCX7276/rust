## Как устроен проект сейчас

```text
rust/
├── Cargo.toml           список зависимостей (Bevy) и настройки сборки
├── .cargo/config.toml   быстрый линковщик rust-lld
├── assets/fonts/        шрифт с русскими буквами
├── docs/                ТЗ, справочник Bevy, этот файл
└── src/
    ├── main.rs          ТОЛЬКО собирает игру из плагинов — логики тут нет
    ├── camera.rs        летающая камера: WASD + мышь
    ├── debug.rs         окно F3: FPS, время кадра, координаты
    └── test_scene.rs    временная сцена: пол, кубы, солнце
```

**Правило:** одна тема — один файл. Новая тема (например, «блоки») → новый файл `src/blocks.rs` → строка `mod blocks;` в `main.rs` → его плагин в `.add_plugins(...)`.

### Как файлы связаны

```text
main.rs
 ├─ mod camera;      → читает src/camera.rs      → берёт camera::CameraPlugin
 ├─ mod debug;       → читает src/debug.rs       → берёт debug::DebugPlugin
 └─ mod test_scene;  → читает src/test_scene.rs  → берёт test_scene::TestScenePlugin
```

Внутри каждого файла одинаково:
1. `pub struct ИмяPlugin;` — плагин (виден из main.rs благодаря `pub`).
2. `impl Plugin for ИмяPlugin { fn build(...) }` — плагин регистрирует свои **системы**.
3. Системы — обычные функции без `pub`: Bevy сам вызывает их и подставляет параметры (`Commands`, `Query`, `Res<...>`).

### Что знакомо по ООП, а что нет

| В ООП (C#, PHP) | В Rust / Bevy |
| --- | --- |
| `class` с полями | `struct` с полями |
| методы класса | `impl Имя { fn метод(&self) }` |
| `interface` | `trait` (например, `Plugin` — это trait) |
| `class X : IPlugin` | `impl Plugin for X` |
| `public` / `private` | `pub` / без `pub` |
| `using` / `include` | `use` / `mod` |
| объект «игрок» с методами Update() | **сущность** с **компонентами** (данные) + **системы** (функции), которые их обрабатывают |
| `null` | `Option`: `Some(значение)` или `None` |
| исключения | `Result`: `Ok(значение)` или `Err(ошибка)` |

Последние три строки — главное отличие. В Bevy у «игрока» нет методов: игрок — это набор данных (`Transform`, `FlyCamera`), а логика — в функциях-системах, которые находят нужные данные через `Query` / `Single`.

- **Не запускать `cargo doc`** — он собирает описание всех 570 пакетов 40+ минут.
- **Не менять `Cargo.toml` без нужды** — правка настроек сборки или версии Bevy = пересборка Bevy заново (10–25 мин).
- **Не копировать код из старых уроков** с `Camera3dBundle`, `PbrBundle`, `EventReader`, `#import` — это старые версии Bevy.
